# 模块文档：API管理中心

最近同步：`2026-04-26`  
状态：`stage1`

## 1. 文档定位

- 本文档只负责第一阶段：界面、结构、入口、占位与边界定义
- 本文档不负责真实官方额度闭环，不提前进入第二阶段接口接入

## 2. 输入文档

- 总规则：`docs/AI_HANDOFF.md`
- 开发总指南：`docs/extension/AI_DEVELOPMENT_PLAYBOOK.md`
- 全局偏好：`docs/extension/全局私人偏好文档.md`
- 新模块清单：`docs/extension/NEW_MODE_CHECKLIST.md`

## 3. 输出文档

- API管理中心第一阶段 UI 结构定义
- 第二阶段真实官方额度接入待补清单
- 本模块的阶段切换条件

## 4. 第一阶段目标

- 给项目里已接入的 API 提供统一查看入口
- 展示每个 API 的当前接入信息、官方已使用、剩余、官方管理中心入口
- 当官方额度无法读取时，明确显示 `?`

## 5. 核心主功能

- 汇总展示当前项目已接入 API
- 提供官方管理中心跳转入口
- 为第二阶段“真实额度读取”预留结构

## 6. 本阶段范围

- 要做：
  - 新增独立模式入口 `I API管理中心`
  - 展示说明条、摘要卡、API 列表表格
  - 从当前本地配置推导出已接入 API 行
  - 为每个 API 提供官方管理中心链接或占位
- 不做：
  - 不直接读取官方 token 用量
  - 不直接读取官方余额
  - 不做额度告警、筛选、分组、统计图

## 7. 第一阶段偏好应用范围

- 采用现有黑白工作型 UI
- 说明条沿用斜杠纹理偏好
- 不引入多余保存按钮，以“刷新本地接入信息”作为阶段内唯一动作
- 不做卡片套卡片；摘要卡与表格维持扁平结构

## 8. 页面入口

- 入口位置：顶部模式栏
- 入口名称：`I API管理中心`
- 用户进入方式：点击模式按钮切换

## 9. 页面结构

- 说明条：
  - 说明当前还是第一阶段，真实官方额度未接入时显示 `?`
- 摘要区：
  - 已登记 API
  - 官方用量读取状态
  - 最近同步时间
- 操作区：
  - 刷新本地接入信息
- 表格区：
  - API
  - 当前接入
  - 已使用
  - 剩余
  - 官方管理中心

## 10. 区块状态表

| 区块 | 当前状态 | 说明 | 下一阶段目标 |
|---|---|---|---|
| 说明条 | 已闭环 | 明确第一阶段边界 | 保留 |
| 摘要区 | 已闭环 | 显示本地推导的汇总信息 | 接真实官方同步状态 |
| API 列表 | 可触发未闭环 | 能展示本地接入信息，但额度仍为占位 | 接入真实用量与余额 |
| 官方入口 | 已闭环 | 可跳转到官方管理中心或占位入口 | 后续补更精确的控制台深链 |

## 11. 关键控件占位

- 按钮：`刷新本地接入信息`
- 状态字段：`已使用`、`剩余`
- 跳转入口：官方管理中心链接

## 12. 默认态 / 空态

- 默认态：
  - 自动列出当前项目已识别 API
  - `已使用` 与 `剩余` 先显示 `?`
- 空态：
  - 当没有识别到已登记 API 时，表格显示空态文案

## 13. 本阶段不做什么

- 不接真实官方配额接口
- 不处理不同厂商鉴权差异
- 不做用量缓存、失败重试、告警机制

## 14. 与现有模块关系

- 依赖 `E截图问答` 的问答 / 语音配置
- 依赖 `D截图发手机` 的上传配置
- 仅做展示，不反向修改原模块业务逻辑

## 15. 第二阶段待补项

1. 接入各官方平台用量 / 余额查询接口
2. 增加读取失败原因与最近成功时间
3. 支持额度告警和低余额提示
4. 支持更多 API 来源接入

## 16. 阶段切换条件

### 允许进入第二阶段的条件

- UI 入口、命名、表格列定义已稳定
- 哪些 API 需要纳入统一管理已经基本明确
- 第一阶段文档已经补齐

### 暂不进入第二阶段的情况

- 仍在频繁改页面结构
- API 列定义还不稳定
- 厂商接入策略与鉴权方式尚未定清

## 17. 第一阶段完成标准

- 用户能从模式栏进入 API管理中心
- 页面能稳定展示已接入 API 的第一阶段清单
- 用量 / 剩余读不到时清楚显示 `?`
- 每个 API 后面都有官方管理中心入口或明确占位
