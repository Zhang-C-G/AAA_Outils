最近同步：`2026-05-20`

## 1. 文档定位

这份文档属于 B 模块第二阶段中的独立能力说明文档。

它专门描述这组已经进入真实工作闭环的正文工作区能力：

1. 正文头部双行工作带
2. 手动保存按钮与自动保存主链并存
3. 正文轻量搜索跳转
4. `最终版本 -> Markdown` 文本锚点定位
5. 目录层级标签持续可见

后续如果继续改正文头部布局、正文视图切换定位、目录标签排布，默认优先以本文档作为实现与验收依据。

## 3. 能力目标

- 把正文头部操作收敛成清楚、稳定的双行工作带
- 在不破坏自动保存主链的前提下，提供手动保存补充入口
- 让正文头部搜索框具备真实可用的跳转能力
- 让用户从 `最终版本` 切回 `Markdown` 时，定位更贴近当前正在看的正文内容
- 保证目录长标题下 `H1 / H2 / H3` 层级标签持续可见

## 4. 用户操作链路

### 4.1 观察正文状态并继续编辑

- 用户做什么：
  - 进入 B 模块正文工作区
  - 观察头部状态点与字数
- 系统如何响应：
  - 第一行左侧固定显示保存状态点与字数
  - 正文内容变化时，状态点与字数同步更新
- 成功后用户看到什么：
  - 能快速判断当前是否处于待保存状态
  - 不需要滚到别处查看保存状态
- 失败时如何提示：
  - 保存失败仍沿用 toast 与状态点 pending 表现

### 4.2 在正文头部手动保存

- 用户做什么：
  - 点击正文头部右上角的 `保存`
- 系统如何响应：
  - 如果当前停在 `最终版本`，先把当前正文 DOM 强制回写到 Markdown 源码
  - 直接触发当前已有保存链路
  - 普通正文走 `saveCurrentNote()`
  - 提取视图走 `saveExtractAggregateView()`
- 成功后用户看到什么：
  - 当前内容被立即落盘
  - 保存状态恢复正常
- 失败时如何提示：
  - toast 提示具体保存失败原因

### 4.3 从最终版本切回 Markdown

- 用户做什么：
  - 在 `最终版本` 浏览或编辑正文
  - 点击 `Markdown`
- 系统如何响应：
  - 先捕获当前视窗第一块可见正文的文本锚点
  - 再切换到 `Markdown`
  - 优先按文本锚点在源码中定位；若匹配不到，再退回标题锚点与滚动比例
- 成功后用户看到什么：
  - `Markdown` 视图落点更贴近刚刚正在看的正文段落
- 失败时如何提示：
  - 当前无单独提示；失败时回退到标题锚点或滚动比例兜底

### 4.4 使用正文头部搜索框

- 用户做什么：
  - 在正文头部搜索框输入关键词
  - 按 `Enter` 跳到下一个匹配，或按 `Shift + Enter` 反向跳转
- 系统如何响应：
  - `Markdown` 视图按源码匹配位置滚动并更新选区
  - `最终版本` 视图按正文文本节点定位，并对命中块做短暂高亮
- 成功后用户看到什么：
  - 正文跳到对应关键词附近
  - 在 `最终版本` 中会看到当前命中块的轻量高亮反馈
- 失败时如何提示：
  - 没有匹配时 toast 提示“没有找到”

### 4.5 扫描长目录标题

- 用户做什么：
  - 在目录中浏览较长标题
- 系统如何响应：
  - 目录标题文本可省略
  - `H1 / H2 / H3` 层级标签保持固定、不可收缩
- 成功后用户看到什么：
  - 即使标题很长，层级标签仍持续可见
- 失败时如何提示：
  - 当前无单独提示；表现异常时应视为样式回归

## 5. 数据链路

- 读取来源：
  - 正文内容：`#noteContent`
  - 最终版本 DOM：`#notePreviewBody`
  - 目录项 DOM：`.notes-outline-item`
- 保存目标：
  - `notes/*.md`
- 默认值：
  - 正文头部默认显示状态点、字数、搜索框、保存、导出与视图切换
  - 正文视图默认 `最终版本`
- 草稿 / 临时态：
  - 搜索框输入值与当前搜索定位状态只属于前端临时态，不写入持久化
  - 预览定位锚点只在切换瞬间使用，不写入持久化
- 刷新后如何恢复：
  - 正文内容、保存状态、目录结构按已保存正文重新生成
- 重启后如何恢复：
  - 重新读取 `notes/*.md`，恢复正文、目录与头部状态显示

## 6. 运行时生效链路

- 保存后是否立即生效：
  - 是
- 是否需要重新加载：
  - 不需要
- 是否依赖其他模块：
  - 不依赖 C 模块数据；B 与 C 仍为独立笔记体系
- 运行态失效时的兜底：
  - 自动保存仍是主链
  - 手动保存只是补充触发入口
  - 保存前先强制同步 `最终版本` 当前 DOM，避免图片、粘贴、拖放等内容看起来已显示但实际没写回源码
  - 文本锚点失配时退回标题锚点与滚动比例

## 7. 允许行为

- 允许正文头部拆成上下两行
- 允许在自动保存主链之外保留一个手动“保存”按钮
- 允许搜索框作为正文工作区内的轻量跳转工具存在于正文头部
- 允许从 `最终版本` 切回 `Markdown` 时优先按文本锚点定位
- 允许长标题省略显示，只要层级标签仍持续可见

## 8. 禁止行为

- 禁止把手动“保存”按钮变成另一套主保存模式
- 禁止因为头部控件增加而破坏正文主工作区尺寸
- 禁止从 `最终版本` 切回 `Markdown` 时总是明显跳偏
- 禁止目录长标题把 `H1 / H2 / H3` 标签挤掉
- 禁止为了定位去强抢 Markdown 文本框焦点

## 9. 异常与边界

- 边界一：
  - 文本锚点定位当前是“第一块可见正文”优先，不是逐像素逐行映射
- 边界二：
  - 当前搜索属于单关键词顺序跳转，不是完整检索面板，也没有结果计数列表
- 异常一：
  - 如果文本锚点匹配不到，必须退回标题锚点或滚动比例，而不是停在错误空白位置
- 异常二：
  - 如果目录标签被标题挤没，视为样式层回归，不能解释为“标题太长属正常”

## 11. 个性化设置类面板硬规则

- 本能力不是传统“设置面板”，而是正文工作区主路径上的高频辅助操作带
- 默认即时生效：
  - 状态点、字数、头部布局、目录标签排布即时反映
- 默认自动保存：
  - 手动保存不替代自动保存
- 默认禁止“保存”“应用”“预览”按钮：
  - 除正文头部这个例外保存入口外，不再额外扩展第二套保存式交互
- 若存在例外，必须明确：
  - 当前例外仅为正文头部 `保存` 按钮
  - 它的作用是主动触发已存在保存链路，而不是改变保存模式
