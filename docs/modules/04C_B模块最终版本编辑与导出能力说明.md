# B 模块最终版本编辑与导出能力说明

最近同步：`2026-05-24`

## 1. 文档定位

这份文档属于 B 模块在第二阶段中的“能力说明文档”。

它专门描述下面这组已经进入真实闭环的能力：

1. `最终版本` 正文直接编辑
2. 选区着色与样式持久化
3. 列表项退回普通正文
4. 自动保存兜底
5. 当前笔记导出
6. 最终版本图片资源文件化落盘

后续如果继续改这几条能力，默认优先以本文档为实现与验收依据，而不是只翻修改过程流水。

## 3. 能力目标

- 让 `最终版本` 从“只读预览”升级为“可直接工作的正文编辑面”
- 保证用户在 `最终版本` 中产生的真实修改都能回写、自动保存、刷新恢复
- 让正文结构编辑不再卡在浏览器原生 marker 行为上
- 让“导出当前笔记”成为稳定可用能力，而不是让用户手动复制

## 4. 用户操作链路

### 4.1 在最终版本中直接编辑正文

- 用户做什么：
  - 切到 `最终版本`
  - 直接在正文区输入、删除、修改内容
- 系统如何响应：
  - 保持同一块正文工作区，不切第二套页面
  - 将 DOM 内容回写为 Markdown 文本
  - 将修改放入自动保存队列
- 成功后用户看到什么：
  - 正文即时变化
  - 切回 `Markdown` 后内容保持一致
- 失败时如何提示：
  - 自动保存失败时用 toast 提示

### 4.2 选区着色

- 用户做什么：
  - 在 `最终版本` 里选中文字
  - 点击悬浮工具条里的文字色或背景色
- 系统如何响应：
  - 对选区追加 `data-note-color` / `data-note-bg`
  - 同类样式按覆盖处理，不继续无限套娃
  - 回写 Markdown，并立即进入静默保存
- 成功后用户看到什么：
  - 当前选区出现对应颜色
  - 切回 `Markdown`、刷新页面、重新打开笔记后样式仍在
- 失败时如何提示：
  - 跨块级结构选区时给出“当前只支持对单段行内文字着色”的提示

### 4.3 退出列表格式

- 用户做什么：
  - 把光标放到某个列表项开头
  - 按 `Backspace` 或 `Delete`
- 系统如何响应：
  - 不依赖选中浏览器原生 marker
  - 把目标行从原列表结构中拆出来，退回普通正文段落
  - 保留前后列表与嵌套块结构
  - 回写 Markdown，并立即进入静默保存
- 成功后用户看到什么：
  - 原来的 `-` / 序号列表格式退出
  - 该行正文仍然存在，不会在自动保存后消失
- 失败时如何提示：
  - 当前实现无单独提示，失败时保持原结构不动

### 4.4 导出当前笔记

- 用户做什么：
  - 在正文头部选择导出格式
  - 点击 `导出当前笔记`
- 系统如何响应：
  - 若当前仍在 `最终版本` 编辑态，先同步回 Markdown
  - 若当前笔记有脏状态，先静默保存
  - 按选中格式生成文件并触发下载
  - 选 `PDF` 时走本地后端生成真实 `.pdf` 文件，而不是只打开打印窗口
- 成功后用户看到什么：
  - 浏览器下载当前笔记文件
  - toast 显示导出格式成功提示
- 失败时如何提示：
  - 导出失败时 toast 提示具体错误
  - 若当前在提取视图，则直接提示先恢复正文再导出

### 4.5 在最终版本中粘贴或拖入图片

- 用户做什么：
  - 在 `最终版本` 中粘贴截图、拖入图片，或保留内嵌 data URL 图片内容
- 系统如何响应：
  - 保存前先把当前 DOM 回写为 Markdown
  - 后端扫描 Markdown 中的 `data:image/...;base64,...`
  - 将图片字节写入 `webui/config/note-assets/<note-id>/`
  - 将正文中的图片引用改写为 `/note-assets/<note-id>/<sha>.<ext>`
- 成功后用户看到什么：
  - 当前正文图片仍正常显示
  - 笔记文件不再残留超长 base64 文本
  - 后续导出、刷新、重开都继续使用文件资源路径
- 失败时如何提示：
  - 图片转存失败时保留原始匹配内容，不阻断本次正文保存

## 5. 数据链路

- 读取来源：
  - 当前笔记正文：`#noteContent`
  - 当前最终版本 DOM：`#notePreviewBody`
  - 当前笔记元信息：`state.notes.currentId / state.notes.list`
- 保存目标：
  - `notes/*.md`
- 资源目标：
  - `webui/config/note-assets/<note-id>/*`
- 结构样式表达：
  - 行内颜色通过 `<span data-note-color="...">` / `<span data-note-bg="...">` 回写到 Markdown
- 默认值：
  - 导出格式默认 `Markdown`
  - 正文视图默认 `最终版本`
- 草稿 / 临时态：
  - 正文输入中的未保存内容存在前端脏状态与自动保存队列
  - 选区工具条与选区范围属于临时前端态，不写入持久化
  - 最近一次已加载版本与最近一次已保存版本会写入 `sessionStorage`，辅助刷新恢复与脏状态校准
- 刷新后如何恢复：
  - 通过已保存的 Markdown 重新解析，恢复正文、目录与着色样式
- 重启后如何恢复：
  - 重新读取 `notes/*.md` 中的正文内容与行内样式标记

## 6. 运行时生效链路

- 保存后是否立即生效：
  - 是
- 是否需要重新加载：
  - 不需要
- 是否依赖其他模块：
  - 不依赖 C 模块数据；B 与 C 仍是独立笔记体系
- 运行态失效时的兜底：
  - 切换笔记、切换模块、刷新前恢复、失焦补保存、选区改色后静默保存
  - 保存成功后以前端接受的服务端规范化正文为准，避免图片路径改写后前后不一致

## 7. 允许行为

- 允许在 `最终版本` 中直接编辑正文
- 允许对单段行内文字追加文字色和背景色
- 允许再次改色时覆盖同类旧色
- 允许在列表项开头通过 `Backspace / Delete` 退出列表格式
- 允许导出当前笔记为 `Markdown / HTML / PDF / TXT / JSON`
- 允许将最终版本中的内嵌图片自动转存为 note-assets 文件资源

## 8. 禁止行为

- 禁止把 `最终版本` 改回只读预览而不更新文档口径
- 禁止删除或削弱自动保存兜底链路
- 禁止让同类颜色无限层层包裹
- 禁止把普通段落直接塞回 `ul / ol` 内形成无效 DOM
- 禁止在提取视图下把聚合内容误导出为单条笔记
- 禁止导出旧内容而不是当前最新正文
- 禁止长期把 data URL 图片原样堆在 `notes/*.md` 中作为正式落盘结果

## 9. 异常与边界

- 边界一：
  - 选区着色当前只支持单段行内内容，不支持跨整块结构一起着色
- 边界二：
  - 列表格式退出只在光标位于列表项开头时触发，不拦截普通位置删除
- 边界三：
  - 提取视图当前不属于“当前单条笔记正文”，因此禁止直接导出
- 边界四：
  - 当前仅自动转存 Markdown 中标准 `![alt](data:image/...;base64,...)` 形式的图片
- 异常一：
  - 如果自动保存失败，必须保留错误提示，不允许静默吞掉
- 异常二：
  - 如果后续继续扩展批量导出或块级编辑，不能复用当前“单条笔记导出”口径直接硬套

## 11. 个性化设置类面板硬规则

- 本能力不属于“主题/样式配置面板”类设置页，但其中的导出格式选择和正文编辑行为仍遵守项目级自动保存与低打扰交互原则
- 默认即时生效：
  - 正文编辑、着色、列表退出均即时反映在正文区
- 默认自动保存：
  - 不再额外要求用户点保存
- 默认禁止“保存”“应用”“预览”按钮：
  - 本能力默认仍不依赖保存式交互；如正文头部保留“保存”按钮，必须明确它不改变自动保存优先级，也不引入第二套确认流程

## 12. 测试清单

- `最终版本` 中直接修改正文后，切回 `Markdown` 内容一致
- 选区着色后，刷新页面与重开笔记样式不丢
- 同类颜色二次修改时覆盖旧色，不叠娃
- 列表项开头按 `Backspace / Delete` 后，该行退回普通正文且自动保存后不吞字
- 目录折叠与复制目录不影响正文主链
- 导出 `Markdown / HTML / PDF / TXT / JSON` 五种格式时，文件内容与当前最新正文一致
- 提取视图下直接导出会被拦住
- 自动保存失败有提示，不静默吞错
- 粘贴或拖入图片后，保存后的 Markdown 应改写为 `/note-assets/...` 路径且图片继续可显示
