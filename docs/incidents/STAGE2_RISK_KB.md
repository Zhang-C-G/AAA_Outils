# 第二阶段风险知识库

最近同步：`2026-04-26`  
状态：`active`

## 1. 文档定位

这份文档不是单次 incident 记录，而是服务第二阶段开发前的通用防错知识库。  
目的只有一个：提高第二阶段“一次完成率”，减少低级返工。

它负责沉淀三类内容：
- 本项目已经反复出现过的第二阶段常见问题
- 跨项目也高频出现的通用断链模式
- 第二阶段实现前必须主动自查的风险点

## 2. 使用时机

出现下面任一情况时，进入第二阶段前应先读本文件：
- 新模块正式进入第二阶段
- 老模块补真实保存 / 加载 / 持久化 / 运行时生效链路
- 高风险模块进入真实开发：悬浮窗、热键、自动保存、截图、麦克风、配置联动
- 同一需求已经出现两轮以上返工迹象

## 3. 核心原则

第二阶段的一次完成，不等于绝不再改。  
它更准确的目标是：

- 主要链路第一次就接对
- 不再反复遗漏同类基础问题
- 不再出现“界面看似好了，底层没接上”的假完成

## 4. 第二阶段高频失败模式

### 4.1 前端做了，后端没接
- 表现：
  - 页面能点
  - 看起来保存成功
  - 实际没有任何真实落盘
- 常见原因：
  - 前端请求根本没发
  - 后端动作没有接收
  - 后端接了但没执行保存

### 4.2 保存了，但没写入本地存储
- 表现：
  - 当前页面内看起来没问题
  - 刷新、重开或重启后内容消失
- 常见原因：
  - 数据只保存在内存态
  - 保存逻辑没有真正写入 `config.ini` / 本地文件
  - 关键字段缺失导致保存被静默跳过

### 4.3 写入了，但没读回
- 表现：
  - 文件里已经有数据
  - 页面回填为空或默认值
- 常见原因：
  - 状态聚合层漏字段
  - 前端初始化没有消费该字段
  - 读取键名和保存键名不一致

### 4.4 页面内刷新正常，浏览器原生刷新不正常
- 表现：
  - 点击页面内刷新按钮没问题
  - 按 `F5` 或浏览器原生刷新后丢状态
- 常见原因：
  - 只做了页面内草稿恢复
  - 没有覆盖原生刷新离开链路

### 4.5 保存后界面变了，但运行时没生效
- 表现：
  - 前端回填、显示都正确
  - 实际热键、悬浮窗、录音、行为逻辑没变化
- 常见原因：
  - 运行时没有 rebind / reload / reapply
  - 只改了配置，没有改执行链路

### 4.6 偏好冲突导致第二阶段返工
- 表现：
  - 功能逻辑本身没错
  - 但 UI 结构、编辑态、按钮形态与全局偏好冲突
- 常见原因：
  - 第一阶段没有前置读取偏好
  - 第二阶段才发现壳子结构不适配

## 5. 本项目已验证过的重点风险

### 5.1 假保存 / 假加载
- 现象：
  - 页面看似保存了
  - 重新进入后数据丢失
- 风险提醒：
  - 必须分清“前端没发、后端没写、重新加载没读回”三层

### 5.2 悬浮窗链路容易只测打开，不测关闭 / 恢复
- 现象：
  - 悬浮窗能开
  - 但关闭、恢复、保护态、再唤起链路容易漏测
- 风险提醒：
  - 用户入口必须测 toggle
  - 内部强制显示链路不能被 toggle 误伤

### 5.3 自动保存只测成功路径，不测恢复路径
- 现象：
  - 正常保存场景没问题
  - 异常退出、原生刷新、重开恢复失败
- 风险提醒：
  - 自动保存链路必须额外测恢复

## 6. 第二阶段开发前必查清单

进入实现前，至少回答下面问题：

1. 用户操作链路写清楚了吗？
2. 保存目标写清楚了吗？
3. 读取来源写清楚了吗？
4. 页面内刷新和原生刷新都考虑了吗？
5. 重启后恢复是否有定义？
6. 运行时是否需要立即生效？
7. 对应全局偏好是否已前置读取？
8. 这次有没有命中历史 incident 中的同类问题？

## 7. 第二阶段实现中必查清单

实现时至少检查四层：
1. 前端显示与回填
2. 后端读取与保存
3. 本地默认值与持久化
4. 运行时真实生效

额外检查：
5. 页面内刷新
6. 浏览器原生刷新
7. 重启主程序
8. 异常路径 / 失败兜底

## 8. 第二阶段测试最低要求

- 当前页面内操作正常
- 页面内刷新后正常
- 浏览器原生刷新后正常
- 本地存储真实写入
- 重新读取结果一致
- 重启主程序后状态一致
- 运行时链路真实生效
- 不破坏旧模块主功能

## 10. 维护方式

- 如果某类问题已经在本项目里反复出现两次以上，应沉淀到本文档
- 如果某个 incident 对未来第二阶段开发有普遍提醒价值，应提炼结论补入本文档
- 不把本文档写成单次事故流水；它只保留可复用的风险结论
