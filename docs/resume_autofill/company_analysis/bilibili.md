# Bilibili 简历填写分析

状态：`首版插件策略已实现`

## 1. 页面判断

- 当前页面是 Bilibili 投递表单的单页长表单
- 已确认包含以下分组：
  - 基本信息
  - 简历解析
  - 教育经历
  - 实习/工作经历
  - 项目经历
- 教育经历、实习/工作经历、项目经历都属于“编号块 + 新增按钮”的列表型分组表单

## 2. 已确认的控件行为

### 2.1 性别

- 不是自由输入框
- 是普通下拉面板
- 当前可见选项为：
  - `男`
  - `女`

结论：

- 性别必须走 `select_option`
- 不应只靠写 `value`
- 策略上可直接按可见文本命中

### 2.2 出生日期

- 不是简单文本框
- 点击后会展开“年-月-日”日历面板
- 当前截图中可见：
  - 顶部年月标题，如 `2002年 3月`
  - 左右翻页箭头
  - 日期格子选择

结论：

- 出生日期应定义为 `pick_date`
- 优先策略不是直接写文本，而是：
  1. 点击输入框
  2. 定位年/月
  3. 点击具体日

### 2.3 教育/实习/项目时间

- 与出生日期不是同一种控件
- 经历时间打开后是“年份 + 月份面板”
- 当前截图确认可按月份点击，如：
  - `一月`
  - `二月`
  - `三月`
  - `四月`
  - ...
- 起止时间格式为 `YYYY-MM`
- 同行存在 `至今` 复选框

结论：

- 经历时间应单独定义为 `pick_month_range`
- 不要复用出生日期的日历策略
- 时间段动作应拆成：
  1. 点击开始时间
  2. 选年份
  3. 选月份
  4. 点击结束时间
  5. 选年份
  6. 选月份
  7. 或结束为空时勾选 `至今`

### 2.4 添加按钮

已确认页面存在以下显式新增入口：

- `添加教育经历`
- `添加实习/工作经历`
- `添加项目经历`

结论：

- 三类经历都需要 `click_add_then_fill`
- 站点策略必须支持“已有块数量不足时自动补点新增按钮”

## 3. 分组字段拆解

### 3.1 基本信息区

| 字段 | 控件类型 | 自动化判断 | 对应本地字段 |
| --- | --- | --- | --- |
| 姓名 | `direct_fill` | 直接输入框 | `full_name` |
| 性别 | `select_option` | 按可见选项文本选中 | `gender` |
| 出生日期 | `pick_date` | 走日历面板 | `birth_date` |
| 所在城市 | `direct_fill` | 普通输入框 | `current_city` |
| 手机号码 | `multi_field_group` | 地区下拉 + 号码输入 | `phone` |
| 邮箱地址 | `direct_fill` | 普通输入框 | `email` |
| 内推码 | `optional_skip` | 默认跳过 | 无 |

### 3.2 简历解析区

| 字段/区域 | 控件类型 | 自动化判断 | 对应本地字段 |
| --- | --- | --- | --- |
| 简历解析文本区 | `direct_fill` | 大文本框，可直接写入 | `self_intro` 或长文本摘要 |
| 附件/解析来源区 | `manual_or_upload` | 第一阶段跳过 | 暂不接 |

### 3.3 教育经历区

每个教育块当前已确认包含：

- 学校名称
- 起止时间
- `至今` 复选框
- 专业
- 学历下拉
- 删除按钮

结论：

- `education_group_strategy` 必须存在
- 每个块都需要按组填充，而不是全局字段乱匹配

### 3.4 实习/工作经历区

当前截图已确认包含：

- 公司名称
- 起止时间
- `至今` 复选框
- 职位名称
- 工作描述
- 删除按钮
- 新增按钮

结论：

- `experience_group_strategy` 可以开始设计具体字段映射
- 这一区的主干字段已经基本够了

建议映射：

- `intern_company` -> 公司名称
- `intern_time` -> 起止时间
- `intern_role` -> 职位名称
- `intern_desc` -> 工作描述

### 3.5 项目经历区

当前截图已确认包含：

- 项目名称
- 起止时间
- 项目角色
- 项目描述
- 项目链接
- 删除按钮
- 新增按钮

结论：

- `project_group_strategy` 应纳入第一版，而不是后补

建议映射：

- `project_name` -> 项目名称
- `project_time` -> 起止时间
- `project_role` -> 项目角色
- `project_desc` -> 项目描述
- `project_link` -> 项目链接

## 4. 动作拆解

### 4.1 基本信息

1. 直接填：姓名、所在城市、手机号主体、邮箱
2. 性别：点开下拉，按 `男/女` 文本点击
3. 出生日期：点开日历，切到目标年月日后点击日期
4. 手机号左侧地区如果已经是中国大陆，不重复操作
5. 内推码默认跳过

### 4.2 教育经历

1. 识别页面已有教育块数量
2. 若本地教育记录更多，点击 `添加教育经历`
3. 对每个块分别填写：
   - 学校名称
   - 起始月份
   - 结束月份或 `至今`
   - 专业
   - 学历

### 4.3 实习/工作经历

1. 识别已有块数量
2. 数量不足时点击 `添加实习/工作经历`
3. 对每个块分别填写：
   - 公司名称
   - 起始月份
   - 结束月份或 `至今`
   - 职位名称
   - 工作描述

### 4.4 项目经历

1. 识别已有块数量
2. 数量不足时点击 `添加项目经历`
3. 对每个块分别填写：
   - 项目名称
   - 起始月份
   - 结束月份或 `至今`
   - 项目角色
   - 项目描述
   - 项目链接

## 5. 当前能优先冲高填充率的点

现在已经不是泛泛而谈了，这几类可以直接作为第一批专用策略目标：

- 基本信息中的姓名、性别、出生日期、城市、手机号、邮箱
- 教育经历中的学校、起止月份、专业、学历
- 实习/工作经历中的公司、时间、职位、描述
- 项目经历中的项目名、时间、角色、描述、链接

只要把：

- 可见文本下拉
- 日历日期选择
- 年月面板选择
- 多段块新增与按序填充

这四类动作稳定下来，Bilibili 这一页已经有希望接近高填充率。

## 6. 当前风险点

### 风险 1：本地数据结构仍偏单条字段

Bilibili 页面已经明确要求多条教育、实习、项目记录。

结论：

- 站点层可以先用“按已有字段拼第一条/有限条记录”的办法顶住
- 但长期仍建议升级本地结构，支持多条教育/多条实习/多条项目

### 风险 2：日期控件分成两类

当前已确认：

- 出生日期是日级日历
- 经历时间是年月面板

结论：

- 绝不能只做一个“通用日期策略”就糊过去
- 至少要拆成 `pick_date` 和 `pick_month_range`

### 风险 3：新增块后的 DOM 索引可能变化

这类页面在点击“添加经历”后，可能：

- 新块插到末尾
- 重新编号
- 重渲染整段列表

结论：

- 每点一次新增后，都要重新查询块列表
- 不要缓存旧节点

### 风险 4：上传区仍不该进入第一轮

虽然截图里上传区还在，但它不是当前最值得冒风险的部分。

结论：

- 第一阶段继续跳过上传

## 7. 第一版 Bilibili 专用策略建议

建议拆成 4 个子策略：

1. `basic_info_strategy`
   - 姓名、性别、出生日期、城市、手机号、邮箱
2. `education_group_strategy`
   - 教育块数量对齐
   - 学校、月份区间、专业、学历
3. `experience_group_strategy`
   - 实习/工作块数量对齐
   - 公司、月份区间、职位、描述
4. `project_group_strategy`
   - 项目块数量对齐
   - 项目名、月份区间、角色、描述、链接

明确先不做：

- 附件上传
- 内推码
- 需要人工判断语义的润色型文本

## 8. 当前实现落地

当前已在浏览器扩展中实现首版 Bilibili 站点策略，文件：

- `browser_extension/resume_autofill/site-strategies.js`

当前已落地的执行结构：

1. `basic_info_strategy`
2. `education_group_strategy`
3. `experience_group_strategy`
4. `project_group_strategy`

当前实现方式：

- 优先按标签文本定位字段
- 列表型经历先判断已有块数量，不足时点击新增按钮
- 时间字段优先写入 `YYYY-MM` 或 `YYYY-MM-DD`
- 下拉字段优先按可见文本点击，失败时回退到直接写值
- 站点策略执行后，再回退给通用填表层补普通字段

当前实现边界：

- 还未接入附件上传
- 还未基于真实 DOM 做定制选择器固化
- 日期控件仍以“写值优先、面板点击兜底”为主，后续可继续强化
