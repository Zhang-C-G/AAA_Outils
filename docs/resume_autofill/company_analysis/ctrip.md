# Ctrip 携程简历填写分析

状态：`截图字段分析已完成`

## 1. 页面判断

- 当前页面是携程投递系统中的“编辑简历”页面
- 页面左侧为：
  - `我的简历`
  - `申请记录`
- 主区当前已确认包含以下分组：
  - 基本信息
  - 教育背景
  - 实习经历
  - 项目经历
  - 获奖经历
  - 自我描述

结论：

- 这不是单纯的投递确认页，而是“站内简历维护页”
- 适合做成 `profile_sync + group_fill` 混合策略

## 2. 已确认的控件行为

### 2.1 基本信息

当前截图已确认可见字段：

- 姓名
- 证件类型
- 证件号
- 手机号
- 邮箱

结论：

- 姓名、证件号、邮箱可优先按 `direct_fill`
- 手机号属于 `multi_field_group`
  - 左侧国家区号
  - 右侧主号码
- 证件类型更像只读或预设值，默认优先 `direct_fill_or_skip`

### 2.2 教育背景日期

当前截图中教育经历使用的是完整日期：

- `入学日期`
- `毕业日期`
- 格式可见为 `YYYY-MM-DD`

结论：

- 携程教育日期优先按 `pick_date` 处理
- 不应直接复用 Bilibili 的 `pick_month_range`
- 若控件允许直接输入，则可在站点层降级为 `direct_fill`

### 2.3 教育背景下拉与细字段

每个教育块当前已确认包含：

- 学校
- 学院名称
- 入学日期
- 毕业日期
- 专业
- 学历
- 绩点
- 成绩排名
- 次专业
- 研究方向
- 导师
- 删除按钮

结论：

- 携程教育块明显比当前默认教育结构更细
- 必须按 `multi_step_group` 处理，不能退化成只填“学校/专业/学历/时间”
- 后续站点策略需要支持：
  - `advisor`
  - `research_direction`
  - `second_major`
  - `education_gpa`
  - `education_rank`

### 2.4 实习经历

当前截图已确认包含：

- 公司
- 职位
- 开始日期
- 结束时间
- 工作业绩
- 删除按钮

结论：

- 实习块主干映射已经足够清晰
- `工作业绩` 为大文本框，应按 `textarea_fill`
- 日期控件同样更接近完整日期，而不是仅年月

建议映射：

- `intern_company` -> 公司
- `intern_role` -> 职位
- `intern_time` -> 开始日期 + 结束时间
- `intern_desc` -> 工作业绩

### 2.5 项目经历

当前截图已确认可见字段：

- 项目名称
- 项目职责
- 删除按钮

当前截图中未明确看到：

- 项目时间
- 项目描述独立字段
- 项目链接

结论：

- 携程项目块第一版不要假设它和 Bilibili 完全一样
- 当前应先保守映射：
  - `project_name` -> 项目名称
  - `project_role` 或项目摘要 -> 项目职责

### 2.6 获奖经历

当前截图已确认每个获奖块包含：

- 获奖时间
- 获奖名称
- 删除按钮

结论：

- 获奖经历可直接作为列表型分组处理
- 第一版优先填：
  - `award_time`
  - `award_name`

- 从版式判断更接近大文本框

结论：

- 第一版可直接映射：
  - `self_intro` -> 自我描述

## 4. 动作拆解

### 4.1 基本信息

1. 直接填写：姓名、证件号、邮箱、手机号主体
2. 若手机号区号不是 `+86`，先切区号
3. 证件类型如已被系统锁定，则跳过不动

### 4.2 教育背景

1. 识别页面已有教育块数量
2. 对已有块按顺序映射本地教育记录
3. 每块优先填写：
   - 学校
   - 学院名称
   - 入学日期
   - 毕业日期
   - 专业
   - 学历
   - 绩点
   - 成绩排名
4. 若本地无 `次专业 / 研究方向 / 导师`，默认留空不乱填
5. 本地资料已补 `education_gpa / education_rank / second_major / research_direction / advisor` 后，优先命中新字段，不再从长文本里临时拆

### 4.3 实习经历

1. 按块填写公司、职位、开始日期、结束日期
2. 将长文本职责写入 `工作业绩`
3. 若文本过长，优先保留高价值内容，不直接截断在句中

### 4.4 项目经历

1. 优先填 `项目名称`
2. 将项目角色或项目摘要压缩写入 `项目职责`
3. 若后续页面展开后出现更多字段，再升级为完整项目组策略

### 4.5 获奖经历

1. 按时间顺序或本地顺序填充奖项
2. 若页面已有块不足，再判断是否需要新增
3. 奖项描述第一阶段默认不扩展到额外字段

## 5. 当前最值得优先支持的策略

- 基本信息：姓名、证件号、手机号、邮箱
- 教育背景：学校、学院、完整日期、专业、学历、绩点、排名
- 实习经历：公司、职位、完整日期、工作业绩
- 项目经历：项目名称、项目职责
- 获奖经历：获奖时间、获奖名称
- 自我描述：自我介绍长文本

## 6. 当前风险点

### 风险 1：教育字段粒度明显高于多数站点默认结构

当前截图里已经确认比 Bilibili 更细的字段：

- 学院名称
- 绩点
- 成绩排名
- 次专业
- 研究方向
- 导师

结论：

- 若只用过于简化的教育字段结构，携程页填充率会明显受限
- 本地资料已开始补 `education_gpa / education_rank / second_major / research_direction / advisor`
- 后续仍建议继续补每段教育经历的结构化记录，而不只依赖长文本摘要

### 风险 2：项目经历字段比其他站点更“瘦”

当前截图只明确看到了：

- 项目名称
- 项目职责

结论：

- 不能先入为主假设存在完整的项目时间、项目链接、项目描述独立字段
- 需要以真实 DOM 为准再做第二轮补全

### 风险 3：完整日期控件与年月控件不能混用

当前携程教育/实习/获奖都更像完整日期：

- `YYYY-MM-DD`

结论：

- 携程应优先复用 `pick_date`
- 不要直接复用 Bilibili 的月份面板策略
