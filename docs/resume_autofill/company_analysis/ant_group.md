# 蚂蚁集团简历填写分析

状态：`截图首轮分析，待补充交互细节`

## 1. 页面判断

- 当前页面是蚂蚁集团招聘投递页中的单页长表单。
- 从截图可稳定识别出的主分区：
  - 简历解析
  - 个人信息
  - 教育经历
  - 实习/工作经历
  - 项目经历
  - 大赛经历与荣誉
  - 其他
- 教育、实习/工作、项目都属于“多段经历块”结构，支持多条记录。
- 页面底部存在 `取消返回` / `保存简历` 操作，说明当前页适合先做“保存型自动填写”，不必强绑定投递提交。

## 2. 已确认的控件行为

### 2.1 简历解析区

- 顶部存在解析入口，文案接近“请先上传或填写个人简历，系统将自动帮你补全简历内容”。
- 当前可视为辅助入口，不是第一阶段必须自动化的主链路。

结论：

- 第一阶段仍以直接填写页面字段为主。
- 上传/解析按钮默认跳过，不作为阻断项。

### 2.2 个人信息区

从截图可确认字段：

- 姓名
- 国家/地区
- 手机号
- 邮箱
- 教育所在城市
- 学校所在城市
- GPA/总分
- 个人 GPA
- 导师
- 双学位
- 研究方向
- 该学历是否应届
- 是否英语授课学校专业
- 删除

结论：

- `姓名 / 邮箱 / 导师 / 研究方向 / GPA` 这类大概率为 `direct_fill`
- `国家/地区` 为下拉选择，按可见文本命中，归入 `select_option`
- `手机号` 是复合字段，左侧区号或国家码，右侧手机号主体，归入 `multi_field_group`
- `教育所在城市 / 学校所在城市 / 双学位 / 是否英语授课学校专业` 大概率为下拉，优先按可见文案选项匹配
- `该学历是否应届` 为复选框

### 2.3 教育经历区

从截图可确认字段：

- 学历
- 时间范围，格式为 `YYYY-MM - YYYY-MM`
- 学校全称
- 所在国家/地区
- 专业
- 专业排名
- GPA/总分
- 个人 GPA
- 导师
- 研究方向
- 该学历是否应届
- 是否英语授课学校专业
- 删除

结论：

- 该区是标准 `education_group_strategy`
- 时间区间属于 `pick_month_range`
- `学历 / 所在国家/地区 / 专业排名 / 是否英语授课学校专业` 偏向下拉
- `该学历是否应届` 复选框需要与结束时间联动处理

### 2.4 实习/工作经历区

从截图可确认字段：

- 时间范围
- 公司名称
- 职位
- 工作描述
- 删除
- 新增经历

结论：

- 当前页把“实习/工作经历”按块管理，核心结构已足够进入专用策略
- `公司名称 / 职位` 走 `direct_fill`
- `工作描述` 走大文本填充
- 时间区间继续复用 `pick_month_range`
- `新增经历` 应归入 `click_add_then_fill`

### 2.5 项目经历区

从截图可确认字段：

- 项目名称
- 起止时间
- 担当角色
- 项目描述
- 项目链接
- 删除

结论：

- 这是标准 `project_group_strategy`
- `项目链接` 是个值得单列的字段，后续可映射到本地自定义字段如 `project_link`
- `项目描述` 是长文本框，适合直接写入

### 2.6 大赛经历与荣誉区

从截图可确认：

- 支持上传文件
- 有独立文本说明区

结论：

- 第一阶段默认跳过上传
- 若后续要补，可拆成：
  - 文本说明
  - 附件上传

### 2.7 其他区

从截图可确认字段：

- 个人主页
- 技术开发语言
- 其他信息
- 你是如何获悉本次

结论：

- `个人主页` 为单行输入
- `技术开发语言` 看起来像标签多选或可编辑标签组，不应按普通 `input` 处理
- `其他信息` 是大文本框
- `你是如何获悉本次` 为下拉

## 4. 动作拆解

### 4.1 个人信息

1. 直接填写姓名、邮箱、研究方向、导师等单行字段
2. 手机号按“国家码/区号 + 号码主体”拆填
3. 对国家/地区、是否英语授课、双学位等下拉使用可见文本选择
4. 应届状态走复选框判断

### 4.2 教育经历

1. 统计页面现有教育块数量
2. 若本地教育记录更多，则寻找新增入口再补块
3. 对每个教育块依次填：
   - 学历
   - 时间范围
   - 学校
   - 国家/地区
   - 专业
   - GPA / 排名 / 导师 / 研究方向

### 4.3 实习/工作经历

1. 识别页面已有经历块数量
2. 数量不足时点击新增
3. 每块依次填公司、时间、职位、工作描述

### 4.4 项目经历

1. 识别已有项目块数量
2. 数量不足时点击新增
3. 每块依次填项目名称、时间、角色、描述、链接

### 4.5 其他

1. 个人主页直接填
2. 技术开发语言优先识别为标签型多选，不先硬写
3. 其他信息走大文本填充
4. 来源渠道按下拉选择

## 5. 风险点

### 风险 1：教育区字段明显多于当前本地默认结构

截图里已经出现：

- 国家/地区
- 个人 GPA
- 导师
- 研究方向
- 英语授课

结论：

- 蚂蚁集团页对教育细节要求比 Bilibili 更细
- 若要提高填充率，需要在本地简历结构中逐步补这些字段

### 风险 2：手机号是复合字段

结论：

- 不能只靠全局文本匹配一个输入框
- 需要单独拆国家码与主号

### 风险 3：技术开发语言可能是标签组件

结论：

- 需要识别标签输入、回车确认、候选项点击，不能先按普通输入框假设

### 风险 4：上传区仍不应进入第一轮

结论：

- 上传文件、简历解析按钮继续默认跳过
- 先把文本和下拉字段跑通

## 6. 第一版蚂蚁集团专用策略建议

建议拆成 5 个子策略：

1. `basic_info_strategy`
   - 姓名、国家/地区、手机号、邮箱
2. `education_group_strategy`
   - 学历、时间、学校、国家/地区、专业、GPA、导师、研究方向
3. `experience_group_strategy`
   - 公司、时间、职位、工作描述
4. `project_group_strategy`
   - 项目名称、时间、角色、描述、链接
5. `misc_strategy`
   - 个人主页、其他信息、来源渠道

明确先不做：

- 简历解析上传
- 大赛经历上传
- 技术开发语言标签多选的复杂交互
