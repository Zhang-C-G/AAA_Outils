# 简历自动投递研究目录

这个目录专门沉淀 F 模块后续要用到的站点填写分析、动作策略和疑难问题。

当前目标不是“能填一些”，而是把简历自动投递拆成可以持续迭代的三层：

1. 通用匹配层  
   负责把本地简历 `flat_map` 映射到普通 `input / textarea / select`
2. 站点策略层  
   负责处理大公司站点里的显式交互，比如下拉、日期、添加按钮、分段经历
3. 问题回收层  
   负责记录失败样本、页面结构差异和后续优化优先级

## 目录结构

- `company_analysis/`
  - 按公司或站点整理填写链路分析
- `issue_log.md`
  - 自动投递过程中的疑难问题台账
- `strategy_notes.md`
  - 通用动作策略口径与实现边界

## 后续工作方式

1. 先收截图或录屏
2. 人工拆解真实填写动作
3. 把动作沉淀进对应公司分析文档
4. 再把稳定动作写进浏览器扩展站点策略
5. 遇到失败样本时，同步记到 `issue_log.md`

## 当前实现进度

- 已完成浏览器扩展通用填表层
- 已完成 `Bilibili` 首个站点专用策略骨架与首版实现
- 当前 Bilibili 策略已覆盖：
  - 基本信息
  - 教育经历
  - 实习/工作经历
  - 项目经历
- 当前仍主动跳过：
  - 附件上传
  - 内推码
  - 需要人工判断的特殊字段

## 90% 填充率目标的口径

- 先覆盖高频字段：姓名、手机号、邮箱、学校、专业、学历、求职期望、时间段、自我介绍
- 再覆盖高频控件：普通输入框、下拉框、日期框
- 最后补齐站点特有动作：添加经历、展开折叠块、切换 tab、二次确认

只要这三层持续滚动，90% 填充率是现实目标，不必一上来就追求全站通吃。
