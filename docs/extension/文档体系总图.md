最近同步：`2026-04-26`

## 1. 目标

- 开发时先读什么
- 第一阶段和第二阶段分别对应什么文档
- 全局私人偏好放在哪一层
- 第二阶段风险知识库放在哪一层

## 3. 推荐阅读顺序

### 3.1 第一阶段

```text
AI 开发总指引
→ 模块主文档
→ 全局私人偏好总入口
→ 与当前 UI 结构、控件样式、交互骨架相关的偏好子文档
→ 第一阶段文档
→ 第一阶段实现
```

### 3.2 第二阶段

```text
AI 开发总指引
→ 模块主文档
→ 标准能力说明文档
→ 全局私人偏好总入口
→ 与本次行为闭环、持久化、运行时生效相关的偏好子文档
→ 第二阶段风险知识库
→ 最终能力说明文档
→ 第二阶段实现
→ 第二阶段测试
```

## 4. 关键理解

### 4.1 第一阶段

第一阶段负责把界面壳层搭出来，但不是脱离偏好自由设计。  
第一阶段必须前置读取：
- UI 结构类偏好
- 控件样式类偏好
- 交互骨架类偏好

目的是避免第二阶段因为偏好冲突返工整个界面。

### 4.2 第二阶段

第二阶段不是直接写代码。  
第二阶段的入口顺序已经固定为：

1. 标准能力说明
2. 偏好映射
3. 风险检查
4. 最终能力说明
5. 实现
6. 测试
7. 记录

### 4.3 风险知识库

`docs/incidents/STAGE2_RISK_KB.md` 不等于单次 bug 文档。  
它是第二阶段开发前的防错输入层，用来减少低级返工。

### 4.4 incident 文档

`docs/incidents/TEMP_*.md` / `RESOLVED_*.md` 用于记录单次真实问题。  
如果某类问题在项目中反复出现，应把通用结论提炼进 `STAGE2_RISK_KB.md`。
