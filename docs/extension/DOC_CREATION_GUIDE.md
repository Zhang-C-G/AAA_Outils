# 文档创建指南

最近同步：`2026-04-26`

## 1. 这份指南解决什么问题

这份指南不是讲“代码怎么写”，而是讲：
- 第一阶段文档怎么建
- 第二阶段能力说明文档怎么建
- 第二阶段风险知识库怎么用
- bug / incident 文档怎么建
- `AI_HANDOFF.md` 怎么更新

## 2. 创建文档前的统一动作

在新建或大改文档前，先做这几步：
1. 先读 `docs/extension/AI_DEVELOPMENT_PLAYBOOK.md`
2. 如果要进入第一阶段或第二阶段，先做 git 检查点
3. 如果能力涉及悬浮窗，再读 `docs/extension/OVERLAY_STAGE2_GUIDE.md`
4. 找到目标模块现有文档：`docs/modules/*.md`
5. 判断这次是“新建文档”还是“在原文档上加新章节”

## 3. 第一阶段文档怎么建

### 3.1 什么时候建
在模块刚进入第一阶段时就要建，不要等界面做完再补。

### 3.2 建在哪里
优先写在对应模块文档里；如当前模块还没有正式模块文档，再先建模块文档。

### 3.3 第一阶段文档必须写什么
至少要写：
1. 文档定位
2. 输入文档 / 输出文档
3. 模块目标
4. 核心主功能
5. 本阶段范围
6. 第一阶段偏好应用范围
7. 页面入口、页面结构、区块状态表
8. 关键控件占位
9. 默认态 / 空态
10. 本阶段不做什么
11. 第二阶段待补项
12. 阶段切换条件
13. 第一阶段完成标准

### 3.4 第一阶段必须前置什么
第一阶段虽然以 UI 为主，但必须前置读取：
- 全局偏好总入口
- 与当前 UI 结构、控件样式、交互骨架相关的偏好子文档

### 3.5 推荐模板
- `docs/templates/STAGE1_DOC_TEMPLATE.md`

## 4. 第二阶段能力说明文档怎么建

### 4.1 什么时候建
不是做完再写，而是：
1. 第一阶段完成后
2. 第二阶段首次真实开发前

### 4.2 建在哪里
优先继续写在模块文档里，新增“第二阶段能力说明”或“能力说明”章节。  
如模块很复杂，也可以单独建一份能力说明文档，但要在模块主文档里明确链接过去。

### 4.3 第二阶段文档必须写什么
至少要写：
1. 文档定位
2. 输入文档 / 输出文档
3. 用户操作链路
4. 数据链路
5. 运行时生效链路
6. 允许行为 / 禁止行为
7. 异常与边界
8. 偏好约束映射
9. 测试清单
10. 本阶段完成标准
11. 恢复锚点

### 4.4 第二阶段前还必须读什么
除标准能力说明外，还必须继续读：
1. 全局私人偏好总入口
2. 与本次能力相关的行为闭环类偏好子文档
3. `docs/incidents/STAGE2_RISK_KB.md`

### 4.5 第二阶段文档最容易漏什么
高频漏项有：
- 只写保存，不写刷新恢复
- 只写页面内刷新，不写浏览器原生刷新
- 只写前端显示，不写后端与本地持久化
- 只写成功路径，不写失败路径
- 不做风险检查，重复踩历史坑

### 4.6 推荐模板
- `docs/templates/STAGE2_CAPABILITY_TEMPLATE.md`

## 5. 悬浮窗第二阶段专项文档怎么补

如果能力带悬浮窗，仅有普通第二阶段文档还不够，还要额外对照：
- `docs/extension/OVERLAY_STAGE2_GUIDE.md`

此时文档里必须明确写清：
1. 显示 / 隐藏 / 关闭 / 恢复
2. 位置记忆
3. 焦点影响
4. 快捷键作用域
5. 保护态 / 防截图 / 防录屏
6. 恢复策略
7. 相关日志点

## 6. bug / incident 文档怎么建

### 6.1 什么时候建
只要出现真实故障、回归、链路断裂、状态不一致，就建。

### 6.2 建在哪里
- `docs/incidents/`

### 6.3 命名规则
- 处理中：`TEMP_YYYY-MM-DD_xxx.md`
- 修复归档后：`RESOLVED_YYYY-MM-DD_xxx.md`

### 6.4 incident 和风险知识库的区别
- incident：记录某一次真实问题
- `STAGE2_RISK_KB.md`：沉淀可复用的第二阶段通用风险结论

### 6.5 推荐模板
- `docs/templates/INCIDENT_TEMPLATE.md`

## 7. AI_HANDOFF 怎么更新

`docs/AI_HANDOFF.md` 不是流水账，而是交接锚点。  
当这些内容变化时必须更新：
1. 当前产品核心
2. 当前优先事项
3. 已知风险
4. 恢复锚点
5. 接手顺序

## 8. 推荐创建顺序

### 8.1 新模块
1. git 检查点
2. 第一阶段文档
3. 第一阶段实现
4. git 检查点
5. 第二阶段能力说明文档
6. 偏好映射 + 风险检查
7. 第二阶段实现
8. 验收
9. 更新 `AI_HANDOFF.md`

### 8.2 旧模块扩展
1. 先判断是第一阶段扩结构，还是第二阶段接链路
2. 进入对应阶段前先做 git 检查点
3. 先补文档，再动代码
4. 验收后补交接与记录
