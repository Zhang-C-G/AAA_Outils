# 模块库总索引

最近同步：`2026-05-09`

## 1. 文档定位

这份文档用于建立本项目的“模块库”机制。  
这里的模块库，不是把现有模块整块复制粘贴，而是把已经反复验证过的结构、交互、闭环和字段组织方式沉淀为可复用母版。

它回答 4 个问题：

1. 为什么要做模块库
2. 模块库里到底放什么
3. 新需求来时，如何判断先选母版还是重新设计
4. 第一批应该优先沉淀哪些母版

## 2. 为什么有必要

当前项目已经反复出现以下模式：

- 目录 + 正文工作区
- 筛选器 + 表格
- 自动保存表单
- 说明条 / 入口条
- 悬浮窗设置面板

如果每次新需求都从零重做，会产生 4 个问题：

1. 重复劳动多
2. 偏好规则容易漏
3. 一轮完成率下降
4. 相似模块之间越做越不像

因此，本项目需要模块库，把“重复出现且已经稳定的东西”抽为可复用母版。

## 3. 模块库的边界

模块库不等于：

- 把整个旧模块原样复制成新模块
- 做一个巨大的万能模板
- 把所有业务字段写死

模块库应该只沉淀：

1. 稳定的页面骨架
2. 稳定的交互规则
3. 稳定的闭环能力
4. 稳定的字段组织方式

真正和具体业务强绑定的内容，仍然留在目标模块里单独定制。

## 4. 结构分层

本项目的模块库默认分为四层：

### 4.1 UI 壳母版

解决“页面长什么样、怎么分区”：

- 目录 + 正文双栏
- 筛选器 + 表格
- 设置面板
- 悬浮窗壳
- 说明条入口条

### 4.2 交互母版

解决“用户怎么操作”：

- 单击切换 / 双击编辑
- 原位编辑
- 目录点击跳转
- 可点击跳转链接
- 展开收起

### 4.3 闭环能力母版

解决“功能怎么真正跑通”：

- 自动保存
- 页面状态持久化
- 视图切换状态恢复
- 筛选器状态恢复
- 分页状态恢复

### 4.4 字段模板

解决“字段怎么组织更稳”：

- 简历字段组
- 公司投递表字段组
- API 管理表字段组
- 笔记目录 / 正文字段组

## 5. 何时必须优先考虑模块库

满足任一条，就优先判断是否可挂入模块库，而不是从零设计：

1. 这类结构已经做过 2 次以上
2. 这类交互已经写过 2 次以上
3. 这类字段维护表只是换字段、换选项、换链路
4. 这类页面和现有模块高度相似
5. 已有私人偏好已经明确约束了这类结构的做法

## 6. 何时不能直接套母版

满足任一条，就不能硬套现有母版：

1. 核心目标和现有母版差异很大
2. 现有母版会明显引入多余区块
3. 现有母版会破坏主路径
4. 现有母版会把业务边界搞混
5. 只是“长得像”，但数据闭环完全不同

## 7. 选母版的顺序

新需求进入后，默认按这个顺序判断：

1. 先判断它更像哪一种页面骨架
2. 再判断它需要哪些交互母版
3. 再判断它需要哪些闭环能力母版
4. 最后只替换字段和业务链路

顺序是：

`先选结构 -> 再挂交互 -> 再挂闭环 -> 最后换字段`

## 8. 当前第一批母版

当前第一批建议正式纳入模块库的母版见：

- `docs/extension/模块母版清单.md`

## 9. 与现有文档体系的关系

- 模块库属于扩展开发规范的一部分，不属于单模块文档
- 模块库用于指导“怎么复用”，不替代模块主文档
- 实际任务进入时，先按 `docs/USER_DOC_SYSTEM_GUIDE.md` 判断当前属于哪类任务，再决定是否需要进入模块库路径
- 真正落地时，仍然要在目标模块文档中写明：
  - 选了哪一个母版
  - 哪些地方沿用
  - 哪些地方做了例外

## 10. 当前执行结论

1. 后续新模块优先从模块库选母版，不再默认从零搭壳
2. 同一类结构重复出现时，应优先沉淀成母版，而不是继续散落在多个模块里
3. 模块库采用“小母版 + 可组合”的方式，不做巨型万能模板
