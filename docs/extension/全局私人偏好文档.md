# 全局私人偏好文档

最近同步：`2026-04-28`

## 1. 文档定位

这份文档不再承担“把所有偏好细则都堆在一起”的职责。  
它只负责四件事：

1. 说明全局私人偏好体系是干什么的
2. 说明第一阶段和第二阶段分别怎么读取
3. 给出当前分层结构和入口
4. 约束后续新增偏好该写到哪里

## 2. 读取顺序

### 2.1 进入第一阶段时

建议按这个顺序读取：
1. `docs/extension/AI_DEVELOPMENT_PLAYBOOK.md`
2. 对应模块文档 `docs/modules/*.md`
3. 本文档 `docs/extension/全局私人偏好文档.md`
4. `00_通用偏好结论.md`
5. 与当前 UI 结构、控件样式、交互骨架相关的偏好子文档

第一阶段的目标不是把所有行为偏好都实现，而是避免先搭出与偏好冲突的壳子。

### 2.2 进入第二阶段时

建议按这个顺序读取：
1. `docs/extension/AI_DEVELOPMENT_PLAYBOOK.md`
2. 对应模块文档 `docs/modules/*.md`
3. 本次标准能力说明文档
4. 本文档 `docs/extension/全局私人偏好文档.md`
5. `00_通用偏好结论.md`
6. 与本次行为闭环、持久化、运行时生效相关的偏好子文档
7. 再与第二阶段风险知识库一起融合成最终能力说明

## 4. 分层说明

### 4.1 总索引层
- 文件：`docs/extension/全局私人偏好文档.md`
- 作用：告诉后续开发这套偏好文档怎么读，不展开细则

### 4.2 通用偏好结论层
- 文件：`docs/extension/global_preferences/00_通用偏好结论.md`
- 作用：提炼默认执行结论，不是原始细则集合

### 4.3 原则层
- 目录：`docs/extension/global_preferences/`
- 作用：存放抽象规则与长期偏好来源

### 4.4 控件专项层
- 目录：`docs/extension/global_preferences/components/`
- 作用：把偏好落到具体 UI 控件与交互细节

## 5. 维护规则

后续新增全局私人偏好时：
1. 先判断它属于原则层还是控件层
2. 写入对应子文档
3. 如无合适位置，再新建子文档
4. 最后只在本总入口补索引，不在这里重复展开长篇细则

## 6. 当前共识

1. 全局私人偏好属于全局层，而不是单模块私有层
2. 第一阶段默认先读总入口，再按需读 UI 类偏好子文档
3. 第二阶段默认先读总入口，再按需读行为闭环类偏好子文档
4. 最终模块方案应把“标准能力说明 + 全局私人偏好结论 + 第二阶段风险检查”融合成最终能力说明

## 7. 与阶段文档和模块文档的协同顺序

为了避免把私人偏好误当成单独生效的散规则，后续统一按下面逻辑协同：

1. 私人偏好不是开工第一入口。
   - 第一入口始终是 `docs/extension/AI_DEVELOPMENT_PLAYBOOK.md`
2. 先判断当前属于第一阶段还是第二阶段。
   - 第一阶段重点避免搭出与偏好冲突的结构壳子
   - 第二阶段重点把偏好映射到真实闭环、持久化、运行时生效和异常边界
3. 再读取目标模块文档。
   - 对应模块主文档 `docs/modules/*.md`
   - 对应模块修改过程文档 `docs/modules/changelog/*.md`
4. 然后再进入私人偏好体系。
   - 先读本总入口
   - 再读 `00_通用偏好结论.md`
   - 再按需进入 UI 结构类、控件类、行为闭环类偏好子文档
5. 最终不是“模块文档替代偏好”，也不是“偏好替代模块文档”，而是要把三者合并：
   - 模块当前正式口径
   - 模块历史修改过程
   - 当前阶段适用的私人偏好结论

执行上必须避免两种错误：
- 只看偏好，不看模块当前边界
- 只看模块功能，不看当前阶段该应用哪些偏好
