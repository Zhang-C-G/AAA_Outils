# 全局私人偏好：表格与筛选器偏好

最近同步：`2026-05-09`

## 1. 文档定位

本文件用于约束“表格型维护界面”该怎么做，尤其是字段越来越多、状态维度越来越多时，应该如何避免只靠横向加列把界面越做越重。

## 2. 默认结论

- 对于表格型维护界面，默认不只靠继续横向加列解决复杂度，而是优先补一层轻量筛选器。
- 对于“公司 / 状态 / 类型 / 规模 / 链接”这类多维维护表，默认偏好是“筛选器 + 表格”组合，而不是只有纯表格。
- 当表格行数持续增长、单屏无法稳定扫视时，默认要补分页，而不是把所有行一次性铺到底。
- 对于中大体量维护表，默认偏好升级为“筛选器 + 分页 + 表格”组合。
- 可筛选列默认不把整套筛选控件长期摊开，优先采用“列标题右侧轻量触发按钮 -> 表格上方出现对应筛选条”的结构。
- 如用户需要同时使用多个筛选维度，顶部筛选条应允许同时展开多个筛选块；对应的多个 `筛` 按钮也应允许同时保持激活色。
- 筛选入口允许用激活态表达当前列正在筛选，但筛选控件本体不要为了区分状态整体改色。
- 对于状态型下拉列，默认保留控件原色；颜色区分优先由侧边色标、状态点、标签承担，而不是直接把下拉框整体染色。
- 表格里的链接列默认采用“单一可编辑输入框 + 单独跳转按钮”，不同时叠一个只读链接和一个编辑框。
- 表格里的短文本字段默认按字段自身职责定宽，不要求机械性撑满整列；像公司名称这类字段应优先贴合自身宽度。
- 对于表头里的批量勾选入口，默认不保留多余文字；如语义已足够明确，只保留勾选框本体，并确保它在该列中真正居中。
- 对于筛选卡片，默认不保留“卡片标题一层 + 控件标签再一层”的重复命名；同一语义只保留一层可见标题。
- 对于公司名称、链接地址这类短文本编辑项，默认应呈现为单行输入外观；只有用户手动换行后，才允许扩展为多行。
- 表格上方的工具区，默认优先提供：
  - 搜索框
  - 状态筛选
  - 类型筛选
  - 清空筛选
- 分页区默认放在表格底部，并优先提供：
  - 当前页
  - 上一页 / 下一页
  - 总条数
  - 每页条数切换
- 当筛选条件能明显减少用户扫描成本时，优先做筛选器，而不是先做更多说明文字。
- 筛选器应保持轻量、扁平、可快速清空，不做重弹窗式高级筛选。
- 分页切换应保持低打扰，不因翻页打断当前筛选条件。
- 筛选条件、每页条数、当前页状态如承担持续浏览职责，默认应自动保存并在重进后恢复。
- 翻页后仍应保持当前筛选条件、当前视图和当前表格上下文，不允许因为分页把用户拉回初始状态。

## 2.1 当前已固化的表格私人偏好

- 顶部筛选区不悬浮在表头旁边，而是出现在表格上方的固定区域。
- 表头只保留轻量筛选触发入口，避免整排筛选器长期占高。
- 分页区默认放在表格底部，承担稳定扫视职责。
- 当前页、每页条数、筛选状态默认自动保存。
- 颜色区分与控件本体解耦，优先使用色标，而不是整控件变色。
- 对于短文本列，输入框优先“内容贴合”，不要求把整格撑满。
- 对于筛选条，默认优先做成紧凑工具条，而不是高占用说明面板。
- 对于多维筛选，允许多个 `筛` 同时激活并同时展开。
- 对于筛选统计，默认在筛选条头部直接显示当前命中总数。

## 2.2 F 模块已验证的表格落地结论

- 公司投递表适合采用“列头圆点筛选 + 顶部筛选条 + 底部分页”的组合。
- 顶部筛选条只通过列头圆点开关，不再额外提供第二套收起入口。
- 筛选条内部应尽量压缩高度，避免比表格本身更抢视觉。
- 公司名称列应收窄为短列，链接列维持可编辑但不额外堆叠说明。
- 表头批量勾选框应居中，且不保留“全选”文字标签。
- 公司名称与链接地址输入框默认单行外观，避免看起来像正文编辑区。

## 3. 分页触发条件

满足任一条，默认应进入分页方案：

1. 单屏已经无法稳定看完当前列表。
2. 行数继续增长后会明显拖慢扫视与定位。
3. 用户会反复回看历史项，而不只是处理最近几条。
4. 表格已经引入多维筛选，说明数据规模已不再适合纯长列表。

## 4. 分页与筛选器的关系

- 分页不是筛选器的替代品。
- 筛选器负责先缩小范围。
- 分页负责在缩小范围后继续保持浏览稳定。
- 不能用“先做了筛选器”作为不做分页的理由。
- 也不能只做分页、不做筛选，让用户靠翻很多页找目标。

## 5. 适用场景

- 公司投递维护表
- API 管理表
- 多字段配置表
- 多状态任务表

## 6. 例外条件

只有当表格字段非常少、状态维度非常少、总行数也非常少、用户几乎不需要回看历史项时，才允许不做筛选器、也不做分页，仅保留纯表格。
