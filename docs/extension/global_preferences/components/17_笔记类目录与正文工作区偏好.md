# 全局私人偏好：笔记类目录与正文工作区偏好

最近同步：`2026-04-28`

## 1. 文档定位

适用于笔记、知识库、长文整理、提取编辑这类“左侧或中侧为目录，右侧为正文工作区”的模块。

这份文档不是单独描述目录，也不是单独描述正文，而是约束“目录区 + 正文区”作为一整套工作区时应如何组织。

## 2. 默认偏好

### 2.1 工作区关系

- 笔记类模块默认采用“目录区服务正文区”的结构，而不是两块彼此独立
- 目录区是正文区的导航镜像，正文区是主工作面
- 用户点击目录时，目标是让正文立即切到对应位置，而不是只在目录区自己高亮

### 2.2 默认布局

- 目录区与正文区默认并列存在
- 正文区默认占主面积，目录区占辅助面积
- 目录列与正文列默认应做成真正的左右同构列，而不是只在功能上并列
- 左右两列的头部标题行，默认统一文字规格、行高、上下间距
- 左右两列下方的主内容框，默认保持顶部线水平一致、底部线也尽量一致
- 如果左右两列高度不能自然一致，默认以正文列为基准去补目录列，而不是反过来压缩正文列
- 正文区必须是稳定工作区，不因模式切换忽大忽小
- `Markdown`、`最终版本`、提取结果等不同正文视图，应共用同一块正文工作区尺寸

### 2.3 正文区视图规则

- 如果同时存在 `Markdown` 输入视图与 `最终版本` 视图，两者应视为同一内容的不同观察方式
- 视图切换不应切出第二套页面，也不应改变正文区尺寸
- 用户切到 `Markdown` 时，看到的是原始表达方式
- 用户切到 `最终版本` 时，看到的是转化后的正常阅读结果
- 视图切换后，目录区仍应继续服务当前正文内容
- `Markdown` 正文框与 `最终版本` 正文框的点击/聚焦反馈应尽量同构，不使用突兀的浏览器原生高亮样式
- 正文框点击后的反馈应低打扰、稳定，不喜欢顶部或边框突然白亮一下的闪变
- `Markdown` 正文框与 `最终版本` 正文框都应保留“可感知但克制”的聚焦反馈，目标是让用户知道当前已进入正文工作态，但不要制造白色闪烁、顶边骤亮、外圈突然跳白这类高刺激变化
- 如果 `Markdown` 正文框必须表现聚焦态，默认优先使用轻量内描边、低对比变化或与 `最终版本` 同方向的细微边界变化，不单独发明另一套更刺眼的焦点语言
- 点击正文框本身只是进入编辑或阅读工作态，不应顺带引发表层结构突变；正文区不应因为一次点击看起来像“切了一个模式”
- `Markdown` 与 `最终版本` 虽然承载方式不同，但只要都属于同一块正文工作区，默认偏好是：点击进去后的气质一致、干扰等级一致、边框变化强度一致

### 2.4 目录与正文联动

- 目录点击默认让正文稳定定位到对应内容位置，不要求强制顶行对齐
- 目录跳转优先即时，不喜欢明显延迟
- 如果当前停在 `Markdown` 视图，而目录跳转依赖 `最终版本` 的结构定位，则应先无感切回 `最终版本` 再跳转
- 目录点击后的正文定位，不应依赖用户再次点击或额外确认
- 目录高亮与正文定位应尽量同步，不制造“目录已变但正文未到”的错觉
- `Markdown` 视图也应具备与 `最终版本` 同方向的目录定位能力，而不是只能在 `最终版本` 下正确跳转
- 目录触发 `Markdown` 定位时，不应为了跳转去抢正文框焦点或制造额外白色闪烁
- 对于同一份内容，目录点击后的跳转体验，`Markdown` 与 `最终版本` 应尽量保持同方向的手感：都应该是“点击目录 -> 正文立即到位 -> 用户继续工作”，而不是一个顺、一个卡、一个稳、一个乱
- `Markdown` 视图下的目录跳转，不要求与 `最终版本` 像素级完全一致，但必须满足三个底线：能到对应标题、定位足够稳定、主观手感不明显弱于 `最终版本`
- 如果 `Markdown` 视图因为换行、字体宽度、可视行高等原因，无法做到和 `最终版本` 完全同位，默认偏好是“尽量贴近正确标题并保持稳定”，而不是为了理论精确引入更强的延迟或闪动
- 目录点击带来的变化应以“正文位置变化”为主，不应再额外叠加与跳转无关的焦点抢占、浏览器原生高亮、整框白闪、光标乱跳等副作用
- 目录触发正文定位后，用户应能立刻继续阅读、编辑或比较内容，不应先被迫处理新的焦点状态、选区状态或视图状态
- 如果目录跳转发生在 `Markdown` 视图，默认更偏好“滚动到位但不抢焦点”；只有用户主动点击正文框时，才进入真正的输入焦点态
- 如果目录跳转发生在 `最终版本` 视图，默认允许轻量高亮当前目标标题，但该高亮应是短暂、柔和、服务定位的，不应喧宾夺主
- 目录与正文联动的默认目标不是“技术上发生滚动”就算完成，而是让用户主观感受到：目录是正文的可靠导航镜像，点哪里就能稳稳看到哪里

### 2.5 正文内容保真

- `Markdown` 到 `最终版本` 的转化，不应破坏原始结构语义
- 独立标签行、段落换行、加粗、斜体、代码等常见 Markdown 表达应尽量保真
- 从 `最终版本` 回写到 `Markdown` 时，不应默认把行内加粗、斜体、代码标记吞掉

### 2.6 提取模式

- 如果正文区支持“提取结果编辑”，提取结果默认仍在主正文区显示
- 不为提取结果再额外开第二正文框
- 提取结果中的标题，默认优先显示真实目录名，而不是抽象占位名

## 3. 禁止倾向

- 不喜欢目录区和正文区像两个不相关面板
- 不喜欢切 `Markdown` 后正文区缩成一小块
- 不喜欢目录跳转只是大概滚到附近，定位看起来不稳定
- 不喜欢最终版本把 Markdown 里的结构语义吞掉
- 不喜欢提取结果继续显示“片段一、片段二”这种抽象占位名
- 不喜欢 `Markdown` 正文框一点击就出现浏览器原生那种突兀白亮焦点感
- 不喜欢目录点完以后，正文虽然跳了，但顺带出现白闪、抢焦点、光标乱跳，打断原本的阅读和编辑节奏
- 不喜欢 `Markdown` 与 `最终版本` 明明属于同一块正文工作区，交互手感却像两个产品

## 4. 默认落地建议

后续只要是“笔记类模块”，默认优先按下面方式落地：

1. 目录区负责结构导航
2. 正文区负责输入、阅读、提取、编辑
3. 左右两列做成同构列，头部和内容框边线尽量对齐
4. `Markdown / 最终版本` 共用同尺寸正文工作区
5. 目录点击后正文稳定定位到对应内容
6. 回写 Markdown 时尽量保留原始结构表达
7. `Markdown` 与 `最终版本` 的目录跳转体验尽量同方向，尤其避免一个稳定、一个明显发飘
8. 正文框的点击与聚焦反馈优先低打扰，不引入白闪、突亮、抢焦点副作用

- C 模块：笔记显示
- 后续所有“目录 + 正文”型笔记模块
