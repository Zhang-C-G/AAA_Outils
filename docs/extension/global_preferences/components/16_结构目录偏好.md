# 全局私人偏好：结构目录偏好

最近同步：`2026-04-28`

## 1. 文档定位

适用于笔记目录、正文目录、章节目录、结构导航区这类“用于定位内容结构”的目录型区域。

这份文档约束的不是某一个模块的业务逻辑，而是目录区在样式、布局、层级表达、交互反馈上的默认偏好。

## 2. 默认偏好

### 2.1 作用定位

- 结构目录的第一职责是帮助用户定位，不是展示装饰
- 结构目录默认属于辅助导航层，不抢正文主区域
- 目录区要优先服务长内容扫描、快速跳转、结构理解

### 2.2 布局

- 目录区默认独立成块，与正文区清楚分开
- 目录区标题、目录操作、目录列表应形成稳定三段结构
- 目录操作优先放在目录区顶部，不埋进二级面板
- 目录区应保留固定工作高度，内容过长时走内部滚动，不把整页撑长
- 目录区与正文区默认并列，不做弹出式临时目录，除非空间极度受限

### 2.3 样式

- 目录区默认走清晰、克制、易扫视的列表样式
- 目录项优先采用整行可点结构，不使用零碎小热区
- 目录项之间应有稳定节奏，方便快速从上到下扫描
- 目录区允许有轻微层次感，但不堆装饰，不做花哨卡片
- 目录区的视觉语言应尽量与同模块中的列表控件保持同构
- 空状态、目录标题、复制按钮等辅助元素应比正文弱一层，不抢主视觉

### 2.4 层级表达

- 目录层级默认通过缩进表达，不依赖复杂图标系统
- `H1 / H2 / H3` 这类层级应有稳定缩进差，不靠随机留白
- 层级样式应保持连续，不制造“某一层突然完全变样”的断裂感
- 如需显示层级标识，应低调、轻量，不抢标题文本本身
- 如目录项后方显示 `H1 / H2 / H3` 标识，默认颜色语义为：`H1` 绿色、且比 `H2` 更重；`H2` 蓝色、并稍微加粗；`H3` 灰色
- 目录文本优先保留标题原意，不擅自改写为摘要句

### 2.5 交互

- 目录项默认单击跳转
- 目录项应整行响应点击，减少点选负担
- 目录跳转不应要求双击触发
- 双击不属于目录导航默认手势，除非该目录项同时承担改名等编辑职责
- 激活态要明确，但不靠闪烁、放大、剧烈跳变提示
- 当前点击后的目录项，默认偏好整行切成白色激活态，包括白色背景与整体反差切换
- 跳转反馈应优先即时响应，不要出现明显延迟
- 如需过渡感，也只能是很轻的视觉反馈，不应让正文滚动本身拖慢点击手感
- 目录点击带来的主要反馈应落在“正文正确到位”这件事本身，不喜欢为了跳转再叠加无关的闪烁、焦点争抢或额外白亮
- 如果目录联动的是可编辑正文区，默认偏好是：跳转服务定位，不额外改写用户当前的编辑节奏
- 复制目录、展开/折叠这类高频辅助动作，应留在目录区主路径
- 如果目录支持折叠，折叠规则必须稳定，不让用户猜当前层级是否还能展开

### 2.6 与正文关系

- 目录区是正文的导航镜像，不应和正文维护两套互相冲突的命名
- 目录项命名应尽量直接来自正文结构
- 目录点击后，应定位到正文对应位置，而不是只做视觉选中
- 目录区默认不承担正文内容展示职责，只负责结构导航
- 如果要做提取、筛选、块级显示，也应尽量复用目录结构锚点

### 2.7 空状态

- 无目录时，应明确告诉用户当前为什么没有目录
- 空状态说明应短，不写成长段教学
- 空状态默认仍留在目录框内部，不额外弹提示

## 3. 禁止倾向

- 不喜欢目录区做成装饰性卡片墙
- 不喜欢目录层级混乱，只能靠猜哪个是上级哪个是下级
- 不喜欢目录项只有一小块文字可点，整行却不能点击
- 不喜欢目录区无限长，把正文区不断往下挤
- 不喜欢目录激活态靠闪动、外扩、放大制造反馈
- 不喜欢目录点击后只做很弱的描边变化，看起来像没选中
- 不喜欢目录和正文标题名称不一致，导致用户认知断裂

## 4. 默认落地建议

后续模块需要实现目录区时，默认优先按下面方式落地：

1. 顶部一行放“目录标题 + 高频操作按钮”
2. 中间主体放整行可点的目录列表
3. 目录层级主要通过缩进表达
4. 目录区内部独立滚动
5. 目录点击后直接定位正文
6. 目录样式尽量向模块内已有列表控件靠拢

## 5. 当前适用范围

- B 模块：重型私人笔记中的结构目录
- C 模块：笔记显示中的目录导航
- 后续其他需要“结构定位”的模块

## 6. 例外规则

如果某个模块因为屏幕空间、交互介质、运行载体限制，无法遵守本偏好，必须：

1. 在该模块第一阶段文档中写明例外原因
2. 在该模块第二阶段能力说明中写明替代方案
3. 避免只在实现里偷偷偏离
